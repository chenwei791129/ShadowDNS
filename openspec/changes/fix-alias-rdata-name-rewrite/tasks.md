## 2. Classification for fail-closed withholding

- [x] 2.1 In the alias package, add a classifier that maps a `dns.RR` to one of three outcomes: `covered` (rrtype handled by `rewriteRDATANames`), `noName` (rrtype whose RDATA has no domain-name field, e.g. A/AAAA/TXT/unknown RFC 3597), and `uncoveredName` (rrtype whose RDATA has at least one domain-name field but is not covered). The "has a domain-name RDATA field" predicate SHALL be derived from the record type's `dns:"domain-name"` / `dns:"cdomain-name"` struct tags via reflection, computed once per concrete Go type and cached (keyed by rrtype or `reflect.Type`) so the hot path performs only a cached lookup. The reflection walk MUST recurse into anonymous embedded struct fields — `dns.HTTPS` is `struct { SVCB }` and its `Target` domain-name tag lives on the embedded `SVCB`, so a top-level `NumField` scan alone misclassifies `HTTPS` as `noName`. The set of `covered` rrtypes SHALL be maintained as an explicit list alongside `rewriteRDATANames` (the type switch cannot be introspected); test 5.4 guards that this list and the switch stay in sync. This implements Decision 2 (fail-closed classification via cached reflection boolean, not a hand-maintained denylist).
- [x] 2.2 Add a `WithheldRecord` value type carrying the withheld record's rrtype and owner name, and a filter that, given a slice of backup answer records, returns `(kept []dns.RR, withheld []WithheldRecord)`: `covered` records go into `kept` (to be rewritten), `noName` records go into `kept` unchanged, and `uncoveredName` records go into `withheld` (excluded from `kept`). The filter MUST NOT depend on a logging package (keep the alias package logger-free). A non-empty `withheld` with an empty `kept` is the signal used by task 3.1 to distinguish "existed but all withheld" (NODATA) from "not found" (stage miss).
